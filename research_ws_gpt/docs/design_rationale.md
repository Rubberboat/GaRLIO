## 코드 대조에서 남긴 확인 사항

다음은 **코드에서 확인됨**이며, 이번 작업에서 알고리즘을 바꾼 목록이 아니다.

- `src/lidarMapping.cpp:600`은 레이더 시각에 맞춰 버퍼를 소비한다. 레이더 대기 조건을 없애면 측정 구간과 뒤의 적분 구간도 달라지므로 단순한 fallback 수정으로 취급하지 않는다.
- `src/lidarMapping.cpp:1560` 부근은 이전 LiDAR 점을 현재 body frame으로 변환해 붙인다. 이전 스캔 저장을 “중복 누적”이라고 가정해 삭제하지 않는다.
- `src/lidarMapping.cpp:1648` 이후는 XY 반경 이웃과 공분산 거리를 계산하지만, 최종 제거는 `pointNKNMahalnobisDistance == 100` sentinel 여부를 사용한다. 식 7의 임계값 방식과 구현을 동일하다고 보고하지 않는다. 차이의 의도·영향은 미확인이다.
- `src/lidarMapping.cpp:1087`의 중력 방향 차이 gate, `1737` 부근의 속도 방향 검사·재갱신, 중력 잔차의 실제 Jacobian 블록은 별도로 검토할 사항이다. 논문의 축약 설명만 보고 불필요하다고 단정하지 않는다.
- `include/filter_state.hpp`의 실제 `StateGroup`에는 외부 보정과 S2 중력 관련 상태가 있다. 논문 식 1의 상태 표기나 주석 처리된 `GlobalState`를 현재 실행 상태와 혼동하지 않는다.

## 변경할 때 남길 기록

각 변경은 해당 논문 절/식, 실제 코드 경로, 해결할 실패 사례, 의존성의 처리, 변경 가설, 검증 결과를 진행 기록에 남긴다. 사용자는 더 나은 대안에 대한 교체·재설계·삭제를 허용했다. 논문과 다른 구현도 설명 가능한 개선 가설이 있으면 자율적으로 진행한다. 단순한 차이만으로 버그나 개선 효과를 확정하지 않는다.

검증은 빌드 → 수치·회귀 검사 → 같은 설정의 bag 비교 → 기능별 ablation 순서로 구분한다. 새 residual/Jacobian은 수치 검증을 포함한다. 기존 기능 OFF는 비교 실험이며 설계 변경과 구별한다. 데이터가 없어도 논리·수치 근거가 있는 개선 구현은 가능하나, 실데이터 성능 주장은 검증 전까지 보류한다. 비교용 원본을 유지한다. 매 push 전 변경 내용·이유·기대 효과·검증 범위를 사용자에게 먼저 설명한다.

이번 변경에서는 루트 C++·헤더·기본 config·launch·빌드 정의가 기준 SHA와 동일함을 Git diff와 소스 hash로 확인했다. 바뀐 부분은 연구 지침, Docker 빌드 공간, 실험 실행·기록 도구다.

## 현재 코드에서 추천하는 첫 개선 후보

아래는 **코드 분석에 따른 제안**이며 아직 구현·성능 측정하지 않았다.

1. **Doppler 가중의 수치 안정성부터 개선한다.** `lidarMapping.cpp:1048`의 식은 `base + base/5 * modifiedZ`다. 조건을 만족하는 `modifiedZ=-5`에서 0, 더 작은 값에서 음수가 되며 뒤에서 이 값으로 나눈다. 양수 하한과 유한값 검사를 두고, 잔차가 작은 관측과 큰 관측을 구별하는 가중을 설계하는 것이 첫 후보이다. 기존에 가장 작은 잔차 1/3을 선택하는 규칙과의 상호작용도 함께 확인해야 한다.
2. **동적 점 제거를 명시적 통계 gate로 비교한다.** 현재 반경 이웃 sentinel 기반 제거와, 좌표계·공분산을 일관되게 적용한 거리 임계값 방식의 오제거/미제거를 비교한다. 정적 구조 보존이 기대 효과이며, 임계값·동적 장면 데이터 검증 없이 더 좋다고 단정하지 않는다.

원본의 목적을 이해한 상태에서 더 나은 설계로 발전시키며, 수치적으로 증명한 사실과 성능 가설을 구별한다.


## 2026-10-22 — 긴급 속도 대입도 기존 관측 품질 기준을 따르게 함

논문 IV-C2는 정적 레이더 관측을 이용한 속도 제약과 이상치 가중으로 잘못된 속도의 영향을 제한한다. 코드의 별도 Angle Refine는 LiDAR 정합이 불안할 때 레이더 속도로 되돌리는 목적이다. 두 경로의 목적은 유효하지만, Doppler 단계가 거부한 속도를 후단에서 무조건 대입하면 앞선 보호를 우회한다. 새 `radar_velocity_guard_gpt.hpp`는 기존 0.5 m/s 축별 기준을 긴급 대입에 적용한다. 검사 기준은 첫 IEKF 갱신 전의 IMU 예측이다. 각 IEKF 반복 내부에서 바뀐 상태로 평가한 Doppler gate의 거부 결과를 그대로 전달하는 구현은 아니므로 모든 거부 경로의 우회가 완전히 사라졌다고 주장하지 않는다. 공분산 모델이나 논문 잔차를 바꾸지 않으며 기존 모드는 실험 플래그 false로 남긴다. 유효한 레이더와 부정확한 예측을 구별하는 더 일반적인 문제는 이 고정 gate만으로 해결되지 않는다. SNAIL 수치는 진행 기록에 별도로 남긴다.

## 2026-10-22 — 실측 IMU 구간과 레이더 스윕 경계의 일치

[논문](https://arxiv.org/html/2502.07703v2)의 III-B 전파, IV-A 레이더 시각 기반 스윕, IV-D 속도 끝점으로부터의 중력 추정은 같은 적분 시간 구간에 의존한다. 원본은 스윕 안에 새 IMU가 없으면 경계를 버리고 마지막 IMU와 스윕 끝 사이를 외삽한다. 긴 실제 IMU 공백에서 스윕 폐기와 반복 외삽이 누적될 수 있다. 목적을 보존하면서 시간 구간을 명시적으로 맞추는 후보를 구현했다.

`mapping/time_consistent_sweeps` 기본 false이며 실험 설정에서만 true로 켠다. `sync_messages()`는 경계 전후의 실제 IMU 샘플을 보존하고, 전파·deskew·중력 적분은 각 샘플 쌍을 정확한 스윕 구간으로 잘라 선형 보간한다. 중력 적분의 가속도 스케일도 전파와 맞춘다. 새 측정 메시지나 가짜 시각을 만들지 않는다. 기존 LiDAR/Doppler/중력 잔차와 Jacobian은 유지하며 초기화에서 미래 샘플의 중복 누적을 막는다.

원본 이산 잡음은 dt² 항으로 들어간다. 같은 측정 구간을 여러 스윕으로 나눌 때 구간 길이/적분 dt로 Q를 조정해 구동 분산의 합을 보존한다. 이는 끝점 재사용의 상관관계를 명시적으로 추정하지 않는 근사이며 완전한 연속시간 공분산 모델이라는 주장은 하지 않는다. 적분 구간·선형 신호 보존과 구동 분산 합을 수치 검사한다.

미래의 **실측** IMU를 기다려야 하므로 센서 시각상의 궤적 공백 감소가 즉시 출력이나 입력 단절 해결을 뜻하지 않는다. `radar_guard.csv`에 실제 IMU 지원 간격, 스윕 길이, 처리 시점의 ROS 시각 지연을 남긴다. 후자는 입력·스케줄링 지연을 포함하며 엄밀한 wall-clock 실행 시간 측정은 아니다. 레이더 자체가 사라지는 경우의 스윕 생성은 별도 문제다.
